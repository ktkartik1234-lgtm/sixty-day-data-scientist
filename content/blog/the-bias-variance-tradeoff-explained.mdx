Every model fails in one of two ways, and every remedy depends on knowing
which failure you have. Get this diagnosis right and model improvement becomes
systematic instead of superstitious.

## The two failure modes

**Bias** is error from wrong assumptions: fitting a straight line to a curve.
The model is too simple to represent the signal, so it fails the same way on
any sample — train and test scores are both poor and close together.
That's **underfitting**.

**Variance** is error from sensitivity to your particular training sample: a
degree-15 polynomial threading through every noisy point. The model fails
differently on each resample — training score is excellent, validation score
is poor. That's **overfitting**.

$$\text{Expected error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible noise}$$

The noise term never goes away; everything you control is the split between
the other two.

## See it in one plot

```python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(0)
X = rng.uniform(0, 1, (60, 1))
y = np.sin(4 * X).ravel() + rng.normal(0, 0.15, 60)

for degree in [1, 4, 15]:
    Xp = PolynomialFeatures(degree).fit_transform(X)
    model = LinearRegression().fit(Xp, y)
    train_mse = mean_squared_error(y, model.predict(Xp))
    print(f"degree {degree:2d}: train MSE {train_mse:.4f}")
```

The degree-1 model trains poorly (bias). The degree-15 model trains
beautifully — and you already distrust it (variance). The degree-4 model is
boring and correct.

<Callout kind="tip" title="The gap is the diagnosis">
  Don't guess from the training score alone. Read the **train/validation
  gap**: small gap, low scores → bias problem. Large gap → variance problem.
  The gap is the single most informative number in your training log.
</Callout>

## Match the remedy to the diagnosis

| Diagnosis | Wrong move | Right moves |
|---|---|---|
| High bias (underfitting) | Regularize harder, add dropout | More capacity, better features, train longer, lower regularization |
| High variance (overfitting) | Keep adding capacity | More data, stronger regularization, simpler model, ensembling |

Adding data fixes variance, not bias — a million examples won't help a model
that's structurally too simple. This is the most common mismatched remedy I
see in code review.
