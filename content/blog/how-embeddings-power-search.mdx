Keyword search matches characters. Embedding search matches *meaning* — which
is why a query for "how do I get my money back" can find a document titled
"Refund policy" without sharing a single content word. Here's the machinery.

## From text to coordinates

An embedding model maps any text to a vector in a high-dimensional space
(typically 384–3072 dimensions) such that **similar meanings land close
together**. "Closeness" is usually cosine similarity — the angle between
vectors, ignoring length:

$$\cos(\theta) = \frac{u \cdot v}{\lVert u \rVert \, \lVert v \rVert}$$

This is the [dot product](/math/linear-algebra/vectors-and-matrices) you met
on Day 2 doing real product work: retrieval, clustering, duplicate detection
and RAG all reduce to "compute and rank dot products."

## The naive search engine, in 15 lines

```python
import numpy as np

docs = ["Refund policy: 30-day returns", "Shipping takes 3-5 days",
        "Warranty covers manufacturing defects"]
query = "how do I get my money back"

D = model.encode(docs)          # (3, d) — in practice, thousands of rows
q = model.encode([query])       # (1, d)
scores = D @ q.T / (np.linalg.norm(D, axis=1, keepdims=True)
                    * np.linalg.norm(q))
print(docs[int(scores.argmax())])   # → the refund policy doc
```

Every vector database is this loop, engineered: the same arithmetic made fast
with ANN indexes and persistent, filtered storage ([Day
37](/roadmap/day/37)).

## ANN indexes: fast approximate neighbors

Exact search scans every vector — fine at thousands, fatal at billions.
Approximate Nearest Neighbor indexes trade a little recall for orders of
magnitude in speed:

- **IVF** — cluster vectors, search only the nearest clusters.
- **HNSW** — a layered graph; hop greedily toward the query. The current
  default in most systems.

You tune a recall/latency dial (`ef_search`, `nprobe`) — measure it with a
held-out set of known-relevant pairs, not vibes.

<Callout kind="tip" title="Chunking beats modeling">
  The most common RAG failure isn't a weak embedding model — it's chunking
  that destroys context: tables split mid-row, paragraphs severed from their
  section headers, code split from its explanation. Chunk by structure (300–800
  tokens, respecting boundaries), overlap slightly, and attach section titles
  to every chunk. This choice moves retrieval quality more than swapping
  models does — measure both ([Day 38](/roadmap/day/38)).
</Callout>

## Where embeddings show up beyond RAG

- **Deduplication** — near-duplicate detection via similarity thresholds.
- **Recommendations** — "related items" as nearest neighbors in item space.
- **Anomaly detection** — documents far from every cluster are worth a look.
- **Classification** — embeddings + logistic regression is a shockingly
  strong text classifier with 50 labels instead of 5,000.
