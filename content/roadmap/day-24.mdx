Yesterday a NumPy net learned by finite differences — conceptually right,
computationally absurd at two forward passes per parameter per step. Today you
replace the cheat with the real algorithm. Backpropagation is the
**[chain rule](/math/calculus/chain-rule-backprop)** organized as an algorithm;
nothing more, and that is exactly why it matters.

## Computational graphs

Every model is a directed graph of simple operations — add, multiply, matmul,
tanh — with known inputs. Each node also knows its **local** derivative. So
once the loss is known, one reverse pass multiplies local derivatives along
every path from loss to parameter. Two facts make this cheap:

1. Each node's gradient is computed once and reused by every path through it.
2. Intermediates from the forward pass ($h$, $z_1$, ...) are cached, not
   recomputed.

Backpropagation is dynamic programming over the graph, and "forward then
backward" is the entire training step.

## The worked example

The smallest interesting network — one scalar input, one hidden unit, one
output, squared loss:

$$z_1 = w_1 x + b_1, \qquad h = \sigma(z_1), \qquad \hat{y} = w_2 h + b_2, \qquad \mathcal{L} = \tfrac{1}{2}(\hat{y} - y)^2$$

Backward pass, one local derivative at a time:

$$\frac{\partial \mathcal{L}}{\partial \hat{y}} = \hat{y} - y \qquad \frac{\partial \mathcal{L}}{\partial w_2} = (\hat{y} - y)\, h \qquad \frac{\partial \mathcal{L}}{\partial b_2} = \hat{y} - y$$

and the interesting one, where the chain rule multiplies three local pieces:

$$\frac{\partial \mathcal{L}}{\partial w_1} = (\hat{y} - y) \cdot w_2 \cdot \sigma'(z_1) \cdot x, \qquad \sigma'(z) = \sigma(z)\,(1 - \sigma(z))$$

Look at what got reused: the error signal $\hat{y} - y$ appears in every
gradient, and $h$ and $z_1$ were already computed going forward. Now notice
$w_2 \sigma'(z_1)$ in the last line: small weights or saturated units shrink
the gradient flowing to early layers. Bookmark that — it becomes vanishing
gradients on Day 30.

## Gradient checking

Never trust a derivation you can check numerically:

```python
import numpy as np

def sigma(z):
    return 1.0 / (1.0 + np.exp(-z))

def loss_and_grads(x, y, w1, b1, w2, b2):
    z1 = w1 * x + b1
    h = sigma(z1)
    yhat = w2 * h + b2
    L = 0.5 * (yhat - y) ** 2
    s = h * (1 - h)                       # sigma prime
    grads = [(yhat - y) * w2 * s * x,     # dL/dw1
             (yhat - y) * w2 * s,         # dL/db1
             (yhat - y) * h,              # dL/dw2
             (yhat - y)]                  # dL/db2
    return L, np.array(grads)

def loss_only(x, y, params):
    return loss_and_grads(x, y, *params)[0]

x, y = 1.3, 0.2
params = [0.7, -0.1, 1.5, 0.3]
_, analytic = loss_and_grads(x, y, *params)

for i, name in enumerate(["w1", "b1", "w2", "b2"]):
    def f(v, i=i):
        trial = list(params)
        trial[i] = v
        return loss_only(x, y, trial)
    num = (f(params[i] + 1e-6) - f(params[i] - 1e-6)) / 2e-6   # central diff
    rel = abs(analytic[i] - num) / max(abs(analytic[i]), abs(num), 1e-12)
    print(f"{name}: analytic {analytic[i]:.8f}  numerical {num:.8f}  rel {rel:.1e}")
    assert rel < 1e-6, f"gradient {name} is wrong"
```

Relative error around 1e-9 is green; 1e-3 means a bug wearing a lab coat. This
exact trick ships inside PyTorch as `torch.autograd.gradcheck`.

## From gradients to learning

The optimizer from the **[gradient descent](/math/optimization/gradient-descent)**
lesson takes over:

$$\theta_{t+1} = \theta_t - \eta \, \nabla_\theta \mathcal{L}(\theta_t)$$

Forward, backward, update — repeat. Everything else in modern deep learning:
momentum, Adam, schedules, Day 26's whole menu, is a refinement of that one
line.

<Callout kind="warn" title="Gradient-checking hygiene">
Check in float64, use central differences (not one-sided), and compare
*relative* error, not absolute. For real-sized layers, check a handful of
random indices only — a full check costs two forward passes per parameter.
Agreement at 1e-7 or better is the standard; anything looser hides real bugs.
</Callout>
