## PR-AUC headlines, ROC-AUC secondary

With a 15 percent positive rate, precision and recall are the honest lens:

$$\text{precision} = \frac{TP}{TP + FP}, \qquad \text{recall} = \frac{TP}{TP + FN}$$

```python
from sklearn.metrics import average_precision_score, roc_auc_score

probs_val = pipe.predict_proba(X_val)[:, 1]
probs_test = pipe.predict_proba(X_test)[:, 1]
print("val  PR-AUC:", round(average_precision_score(y_val, probs_val), 3),
      "| ROC-AUC:", round(roc_auc_score(y_val, probs_val), 3))
print("test PR-AUC:", round(average_precision_score(y_test, probs_test), 3),
      "| ROC-AUC:", round(roc_auc_score(y_test, probs_test), 3))
print("random PR-AUC baseline:", round(y_val.mean(), 3))
```

Report PR-AUC as the headline because it resolves the class imbalance; keep
ROC-AUC as secondary because stakeholders know it. Quote both against the
prevalence baseline, so nobody mistakes an accuracy-style number for skill.

## Calibration: why bankers care

A score is a *ranking*; a probability is a *contract*. If the model says 0.30,
roughly 30 percent of such customers should in fact be stressed — that is
what lets a bank size an intervention, set a limit, or price an offer. Plot
the reliability curve, compute the Brier score,

$$\mathrm{Brier} = \frac{1}{n}\sum_{i=1}^{n}(p_i - y_i)^2,$$

and repair miscalibration with a mapping fit on validation rows, applied
unchanged to test rows (inside a full pipeline, that is
`CalibratedClassifierCV`'s job):

```python
from sklearn.calibration import calibration_curve
from sklearn.isotonic import IsotonicRegression
from sklearn.metrics import brier_score_loss

frac_pos, mean_pred = calibration_curve(y_val, probs_val, n_bins=10)

iso = IsotonicRegression(out_of_bounds="clip")
iso.fit(probs_val, y_val)                 # calibrate on validation
probs_cal = iso.predict(probs_test)       # apply, unchanged, to test

print("Brier before:", round(brier_score_loss(y_test, probs_test), 4))
print("Brier after :", round(brier_score_loss(y_test, probs_cal), 4))
```

## Threshold as a business decision

The default 0.5 encodes "a false alarm and a miss cost the same" — rarely
true. Give the errors prices and let the threshold fall out: a calibrated
score flags a customer exactly when the posterior, which Bayes' rule builds
from likelihoods and the base rate $\pi$, crosses it —

$$P(y=1 \mid x) = \frac{P(x \mid y=1)\,\pi}{P(x \mid y=1)\,\pi + P(x \mid y=0)\,(1-\pi)}$$

```python
best_t, best_cost = None, float("inf")
for t in [i / 100 for i in range(5, 96)]:
    pred = probs_cal >= t
    fn = ((~pred) & (y_test == 1)).sum() * 10.0   # missed stress
    fp = (pred & (y_test == 0)).sum() * 1.0       # needless outreach
    if fn + fp < best_cost:
        best_t, best_cost = t, fn + fp
print("cost-minimising threshold:", best_t, "at total cost", best_cost)
```

With a 10-to-1 cost ratio the optimum lands well below 0.5. Write the cost
matrix into the README — it is a policy statement someone will query.

## Error analysis by cohort slices, with uncertainty

Aggregate metrics hide exactly the failures that matter: slice the test set
by segment, region, earning pattern and age band, then put a bootstrap
confidence interval on the headline number.

```python
import numpy as np

def slice_report(mask, name):
    ap = average_precision_score(y_test[mask], probs_cal[mask])
    print(f"{name:>28}  n={int(mask.sum()):>6}  PR-AUC={ap:.3f}")

for seg in X_test["segment"].unique():
    slice_report(X_test["segment"] == seg, f"segment={seg}")

def bootstrap_pr_auc(y, p, n_boot=1000, seed=42):
    rng = np.random.default_rng(seed)
    scores = []
    for _ in range(n_boot):
        idx = rng.integers(0, len(y), len(y))
        if y.iloc[idx].nunique() < 2:
            continue
        scores.append(average_precision_score(y.iloc[idx], p[idx]))
    return np.percentile(scores, [2.5, 97.5])

lo, hi = bootstrap_pr_auc(y_test.reset_index(drop=True), probs_cal)
print("95 percent CI for test PR-AUC:", round(lo, 3), "to", round(hi, 3))
```

A point estimate is a promise you cannot keep; the interval is the honest
version, and it goes in the README next to every reported metric.

<Callout kind="deep" title="Great AUC, broken bank">
  Nothing about a high PR-AUC prevents the deployed model from being useless:
  ranking is not pricing. A model can order customers perfectly and still be
  undeployable if its probabilities are miscalibrated or its threshold was
  set by default. Headline metric, calibration curve, cost-based threshold —
  the trio is the minimum honest evaluation for any financial decision
  system; report all three or report none.
</Callout>
