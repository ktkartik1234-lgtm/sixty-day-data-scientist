You have called it log loss, binary cross-entropy, categorical cross-entropy
and negative log-likelihood. They are all the same object: the cross-entropy
between the true labels and your model's predicted distribution.

## From KL to the loss

Cross-entropy is entropy plus divergence — the average number of bits needed
to encode events from $P$ using a code built for $Q$:

$$H(P, Q) = H(P) + D_{KL}(P \,\|\, Q)$$

When you train a classifier, $P$ is fixed (the data), so $H(P)$ is a constant.
Minimizing cross-entropy is therefore **exactly** minimizing
$D_{KL}(P \| Q)$ — maximum likelihood in disguise.

## The form you know

For one example with true class $y \in \{0, 1\}$ and predicted probability
$\hat{p} = P(y = 1 \mid x)$:

$$\mathcal{L} = -\big[\, y \log(\hat{p}) + (1 - y)\log(1 - \hat{p}) \,\big]$$

The logarithm makes confident mistakes ruinous: predicting $\hat{p} = 0.99$
when the truth is 1 costs a puny $0.01$ nats; predicting $0.01$ costs
$\log(1/0.01) \approx 4.6$. Correct and confident predictions cost almost
nothing; correct and timid predictions cost a little.

<Callout kind="tip" title="How to read a training curve">
  Cross-entropy has a floor: it cannot go below the data's own entropy
  $H(P)$ (irreducible label noise). When your training loss plateaus around
  $H(P)$ plus a little, the model has extracted what the features allow —
  more capacity won't help, better features will.
</Callout>

## Why softmax + cross-entropy travel together

Multi-class models output raw scores (logits) $z_1 \dots z_k$, turned into a
probability distribution by the softmax:

$$\text{softmax}(z)_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

Feeding those probabilities into cross-entropy gives a beautiful simplification:
the gradient of the loss with respect to the logits is just
$\hat{p} - y$ — prediction minus truth. Simple, stable, no vanishing-gradient
trap. That algebra is why this pairing became the default for every classifier,
from logistic regression (Day 16) to GPT's next-token head (Day 31).

## In code

```python
import numpy as np

def cross_entropy(y_true, y_pred):
    y_true, y_pred = np.asarray(y_true), np.asarray(y_pred)
    return -np.mean(np.sum(y_true * np.log(y_pred + 1e-12), axis=1))

# one-hot true label vs two predictions for the same example
cross_entropy([[1, 0]], [[0.8, 0.2]])   # 0.223 — confident and right
cross_entropy([[1, 0]], [[0.2, 0.8]])   # 1.609 — confident and wrong
```

## Worked problem

<Callout kind="info" title="Problem">
  Model A predicts probability 0.6 for the true class; model B predicts 0.9.
  Compute each binary cross-entropy loss (natural log) and how many times
  costlier a confident error (predicting 0.9 for the wrong class) is than a
  confident correct answer.
</Callout>

<Solution>
  $$\mathcal{L}_A = -\log(0.6) \approx 0.511 \qquad \mathcal{L}_B = -\log(0.9) \approx 0.105$$

  A confident error against the true class: $-\log(0.1) \approx 2.303$ — about
  22 times the loss of the confident correct prediction. This asymmetry is the
  training signal: the optimizer learns that confident wrongness is the worst
  thing it can do, which is precisely the behavior you want from a
  probability estimator (and what calibration curves measure on Day 58).
</Solution>
